## 1. 背景与决策摘要

### 1.1 架构立场（当前）

| 层级 | 技术 | 职责 |
|------|------|------|
| `front/` | Vue 3 + TS + Element Plus + UnoCSS | UI；消费 OpenAPI 生成类型 |
| `backend/` | FastAPI + Pydantic | **对外 API 与领域契约真相源**；业务库；入库编排；问答编排 |
| `shared/` | OpenAPI → TypeScript | 禁止手写平行 DTO |

**明确暂缓**：用 Go 做 CRUD/微服务、用 Redis 做缓存/队列——只记演进，**不进本期验收**。Python 继续承担后端 + 后续爬虫/解析/RAG/Agent；拆分时再把「增删改查中台」与「AI 能力」切开。

### 1.2 本期要做的四件事（边界）

| 主题 | 本期含义 | 不包含 |
|------|----------|--------|
| 多用户知识空间 | 注册登录；Workspace 按 Owner 隔离 | 成员协作、角色、分享链接 |
| 数据库设计 | 逻辑模型 + 表字段；业务库与向量库分离 | 上生产级分库分表 |
| 多 SourceType | `plain_text` + `markdown` + `web_page`（单页） | Office/图片/视频、整站爬 |
| RAG 入库与问答 | 异步入库；严格边界问答 + 引用；会话落库 | 边界优先/开放研究、多 Agent |

### 1.3 与 MVP 的关系

```text
Phase 1（已有）  知识空间 CRUD + plain_text CRUD + SSE 心跳
        ↓
Phase 2a         用户与归属
Phase 2b         plain_text 打通 RAG（分块→嵌入→严格问答→引用）
Phase 2c         扩展 markdown / web_page
```

MVP 接口在 2a 起增加鉴权；资源必须校验 Owner。存量无主数据：开发阶段允许 **清空库重建**，或提供一次性迁移脚本将旧 Workspace 挂到指定用户（二选一写进实现 README，推荐清空重建以降低成本）。

## 2. 产品规则

### 2.1 用户与认证

- 标识：中国大陆手机号（配置项 `PHONE_REGEX`）。
- 注册 / 登录：手机号 + 密码；签发 JWT Access Token（无 Refresh）。
- **后续**：手机号验证码登录（配置占位见配置说明，本期不实现、不验收）。
- 同一手机号仅能注册一次。

### 2.2 知识空间隔离

- 每个 Workspace 有且仅有一个 `ownerId`。
- 列表/详情/改删/投递来源/会话/问答：只能操作自己的空间。
- 越权或不存在：统一 `404`（避免探测他人资源）。

### 2.3 来源与入库管道

```text
创建 Source → status=pending
    → worker：processing
    → 规范化正文 → Chunk → Embedding → 向量库
    → ready | failed（写 errorMessage）
```

- 仅 `ready` 的来源进入检索。
- 创建接口立即返回，前端 **轮询** Source 状态（SSE 任务事件为后续增强，本期不强制）。
- 删除 Source：删业务库记录、Chunk 元数据、**向量库中对应向量**。
- 删除 Workspace：级联删除其下 Source、Chunk、向量、Conversation/Message。

### 2.4 SourceType（初期落地集）

| type | 输入 | 规范化结果 | 里程碑 |
|------|------|------------|--------|
| `plain_text` | title? + content | 正文即 content | 2b |
| `markdown` | title? + content（或文件正文） | 保留 Markdown 文本 | 2c |
| `web_page` | title? + url | 抓取后提取正文，写入 content；保留 url 元数据 | 2c |

其它枚举值若出现在创建请求中 → `400`。

`web_page` 硬限制：仅 `http/https`；超时与最大字节见配置；无登录态站点、无整站爬、无 Playwright（后续再议）。

### 2.5 问答（严格边界）

- 必须指定 `workspaceId`（及所属会话）。
- AnswerMode 固定 `strict`：无可靠检索证据时，返回配置文案 `STRICT_NO_EVIDENCE_REPLY`，不得编造。
- 有证据时：生成回答并附带 Citation（sourceId、chunkId、标题、可选片段预览）。
- 多轮：会话内保存历史；检索仍按**当前问题**；把最近 `CHAT_HISTORY_MESSAGE_LIMIT` 条消息交给聊天模型；**不做**独立 Query 改写 Agent。

### 2.6 模型配置

- **系统默认档**：来自环境变量（聊天 / 嵌入可分开）；前端列表标注 **「默认」**。
- **用户 ModelProfile**：服务端存储；`purpose = chat | embedding`；API Key **只写不完整回读**（脱敏，可见后缀长度见配置）。
- 问答/入库时由后端取 Key 调用 OpenAI 兼容 HTTP API。
- 默认未配置且用户未建档：相关接口返回明确错误（不静默降级）。

## 3. 里程碑与验收

### Phase 2a — 用户与空间归属

| 验收项 | 标准 |
|--------|------|
| 注册登录 | 手机号+密码可注册、登录，获得 Token |
| 隔离 | 用户 A 无法读写用户 B 的 Workspace/Source |
| 归属 | 新建 Workspace 自动带当前用户 `ownerId` |
| 契约 | OpenAPI 含 Auth 相关 schema；前端生成类型 |

**前端**：登录/注册页；请求头带 Bearer；未登录跳转登录。

### Phase 2b — plain_text RAG 闭环

| 验收项 | 标准 |
|--------|------|
| 异步入库 | 创建后为 pending/processing，完成后 ready；失败可见原因 |
| 分块嵌入 | ready 后来源可被检索（向量库有数据） |
| 会话 | 可创建 Conversation，收发 Message |
| 严格问答 | 无相关内容时固定拒答文案；有内容时回答含 Citation |
| 级联删除 | 删 Source/Workspace 后向量侧无残留（抽查） |
| 模型 UI | 可查看默认档（标注默认）、可增删改个人档（Key 脱敏）、问答可选模型 |

**前端**：空间详情展示来源状态；会话页；模型设置页。

### Phase 2c — markdown / web_page

| 验收项 | 标准 |
|--------|------|
| markdown | 可创建并入库至 ready，可被问答引用 |
| web_page | 合法 URL 单页采集成功；超时/过大/非法 scheme → failed |
| 统一管道 | 三种类型共用分块配置项，无散落魔法数 |

## 4. 逻辑数据模型

业务库（SQLite 可继续）与向量库分离：**Chunk 文本与关系在业务库；向量在 Chroma（可配）**。

### 4.1 ER 关系（逻辑）

```text
User 1──* Workspace
User 1──* ModelProfile
Workspace 1──* Source
Workspace 1──* Conversation
Source 1──* Chunk          （业务元数据）
Conversation 1──* Message
Message *──* Citation      （可内嵌 JSON，不必独立表）
```

### 4.2 表 / 实体字段

JSON API 继续 **camelCase**；库内 **snake_case**。

#### users

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string UUID | PK |
| phone | string | 唯一 |
| password_hash | string | |
| created_at / updated_at | datetime | |

#### workspaces（相对 MVP 增量）

| 字段 | 说明 |
|------|------|
| owner_id | FK → users.id |
| （其余同 MVP：name, description, timestamps） | |
| source_count | 可冗余维护或查询聚合 |

#### sources（相对 MVP 增量）

| 字段 | 说明 |
|------|------|
| type | plain_text / markdown / web_page |
| status | pending / processing / ready / failed |
| content | 规范化后正文（web 为提取正文） |
| source_url | 可空；web_page 必填 |
| error_message | 可空 |
| （title, workspace_id, timestamps…） | |

#### chunks

| 字段 | 说明 |
|------|------|
| id | UUID |
| source_id / workspace_id / owner_id | 冗余便于过滤与级联 |
| ordinal | 来源内序号 |
| content | 块文本 |
| content_preview | 短预览 |
| vector_ref | 可选，向量侧 id |
| created_at | |

#### conversations

| 字段 | 说明 |
|------|------|
| id | UUID |
| workspace_id / owner_id | |
| title | 可空，默认取首问前缀 |
| created_at / updated_at | |

#### messages

| 字段 | 说明 |
|------|------|
| id | UUID |
| conversation_id | |
| role | `user` \| `assistant` \| `system`（system 慎用） |
| content | |
| citations_json | 助手消息的引用列表 |
| created_at | |

#### model_profiles

| 字段 | 说明 |
|------|------|
| id | UUID |
| owner_id | 用户档；系统默认可不入表或 owner_id 空 + 标记 |
| name | |
| purpose | chat / embedding |
| base_url | |
| model_name | |
| api_key_encrypted | 服务端保管（至少不可明文日志；实现可选加密 at rest） |
| is_system_default | 系统档为 true，前端标注「默认」 |
| created_at / updated_at | |

系统默认也可用纯环境变量、接口组装成只读 Profile（`isSystemDefault=true`），不强制入库。

### 4.3 向量库

- Collection 名、路径见配置说明。
- 每条向量 metadata：`chunk_id`, `source_id`, `workspace_id`, `owner_id`。
- 检索过滤：必须 `workspace_id = 当前空间`（且属于当前用户）。

## 5. API 范围（相对 MVP 的增量）

Base：`/api/v1`。除登录注册与健康检查外，均需 `Authorization: Bearer <token>`。

### 5.1 Auth

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/register` | phone + password |
| POST | `/auth/login` | 返回 accessToken |
| GET | `/auth/me` | 当前用户 |

### 5.2 Workspace / Source

- 沿用 MVP 路径；全部加 Owner 校验。
- Source 创建：`type` 可为三种之一（按里程碑放开）；返回含 `status`。
- `web_page` body：`url` 必填；`markdown`/`plain_text`：`content` 必填。

### 5.3 Conversations / Ask

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/workspaces/{id}/conversations` | 创建会话 |
| GET | `/workspaces/{id}/conversations` | 列表 |
| GET | `/conversations/{id}` | 详情含消息（或分端点） |
| DELETE | `/conversations/{id}` | 删会话与消息，不动 Source |
| POST | `/conversations/{id}/messages` | 用户提问；服务端检索+生成；写回 user/assistant 消息 |

提问可选：`chatModelProfileId`、`embeddingModelProfileId`（缺省用默认档）。

### 5.4 Model profiles

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/model-profiles` | 含系统默认（标注）+ 当前用户档；Key 脱敏 |
| POST | `/model-profiles` | 创建用户档 |
| PATCH | `/model-profiles/{id}` | 更新（Key 不传则保留） |
| DELETE | `/model-profiles/{id}` | 不可删系统默认 |

### 5.5 SSE

- MVP 心跳保留；2a 后建议需登录（Token 查询参数或头，按实现选型并在 OpenAPI 注明）。
- 入库进度本期以轮询 Source 为准。

契约仍：**Pydantic → OpenAPI → `shared` 生成 TS**。

## 6. 前端范围

| 页面/模块 | 里程碑 | 要点 |
|-----------|--------|------|
| 登录 / 注册 | 2a | 手机号校验；Token 持久化 |
| 空间列表/详情 | 2a 改造 | 仅自己的数据；来源状态展示 |
| 来源投递 | 2b/2c | 按类型切换表单（文本 / MD / URL） |
| 会话与问答 | 2b | 引用可点击或展示来源标题；无证据展示固定文案 |
| 模型设置 | 2b | 默认档标注；个人档 CRUD；Key 密码框只写 |

样式与组件：遵循仓库 UnoCSS / Element Plus / 可点击 hover 等既有规则。

## 7. 后端实现要点

1. **配置**：扩展现有 `Settings`，键名与 [配置说明](./配置说明.md) 一致；校验用配置常量。  
2. **密码**：哈希存储；日志禁止打印密码与完整 API Key。  
3. **Worker**：可用 asyncio 后台任务或简单轮询线程；进程重启后继续处理 `pending`。  
4. **分块**：Phase 2 统一 `CHUNK_SIZE_CHARS` / `CHUNK_OVERLAP_CHARS`；按标题切割列为后续优化。  
5. **删除顺序**：先删向量，再删业务行（或事务内可恢复策略需文档化）；失败要可重试清理。  
6. **严格模式 Prompt**：指示模型仅依据给定片段作答；应用层若检索为空则直接短答，不调用或调用后仍以空检索为准。
