# 知域 KnowledgeScope — 本地启动说明

> 面向本地开发：把 `backend`（FastAPI）+ `front`（Vite）两个进程跑起来。
> 契约层 `shared` 只在改了后端模型时需要重新生成，日常启动不必执行。
> 端口、命令与仓库现有脚本一致，改动脚本时请同步本文件。

| 服务 | 目录 | 地址 |
|------|------|------|
| 后端 API | `backend/` | `http://127.0.0.1:8000` |
| 接口文档 | `backend/` | `/docs`、`/redoc`、`/openapi.json` |
| 健康检查 | `backend/` | `GET /health`（无需登录） |
| 前端 | `front/` | `http://127.0.0.1:5173` |

开发态前端把 `/api`、`/health` 代理到后端 `8000`，因此不需要额外处理 CORS，SSE 也同源。

---

## 1. 前置条件

- Python ≥ 3.11（用 `backend/.venv`，不要用全局 base 环境）
- Node.js ≥ 20
- 只需首次执行一次的依赖安装（见第 2 节）

---

## 2. 首次准备（只做一次）

### 2.1 后端虚拟环境与依赖

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

### 2.2 环境变量

```powershell
cd backend
Copy-Item .env.example .env
```

`.env` 至少确认：

- `JWT_SECRET_KEY` 已改成本地值（`dev-only-change-me-knowledgescope` 仅示例）
- `DEFAULT_CHAT_*` / `DEFAULT_EMBEDDING_*` 六项已填，否则入库与问答会直接报「未配置模型」，不会静默降级
- `DATABASE_URL` 默认 `sqlite:///./data/knowledgescope.db`；首次启动会自动建 `backend/data/` 与建表

键名与默认值见 [`配置说明.md`](配置说明.md)。

### 2.3 前端依赖

```powershell
cd front
npm.cmd install
```

### 2.4 契约层（仅当后端 schema 有改动）

```powershell
cd shared
npm.cmd install
npm.cmd run generate
```

`generate` 直接调用 `backend/.venv` 中的 Python 导出 OpenAPI，**不需要先启动 uvicorn**。生成产物 `shared/openapi/openapi.json`、`shared/generated/openapi.ts` 需随代码一起提交。

---

## 3. 日常启动（两个终端）

### 终端 1 — 后端

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

用 `python.exe` 直接调用，可跳过 PowerShell 的脚本激活策略问题。

### 终端 2 — 前端

```powershell
cd front
npm.cmd run dev
```

浏览器打开 `http://127.0.0.1:5173`；未登录会跳 `/login`，先注册或登录再进知识空间。

### 一条命令拉起两个进程（可选）

在仓库根目录执行，新开窗口并行启动，日志各自输出：

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','cd backend; .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000'
Start-Process powershell -ArgumentList '-NoExit','-Command','cd front; npm.cmd run dev'
```

## 4. 启动后自检

```powershell
# 后端存活
curl.exe http://127.0.0.1:8000/health

# 前端页面可访问（返回 200）
curl.exe -I http://127.0.0.1:5173/
```

期望结果：`{"status":"ok"}` 与 `200`。

走一遍最短闭环：

1. 登录 / 注册（手机号 `^1\d{10}$` + 密码）。
2. 创建知识空间。
3. 投递 `plain_text` / `markdown` / `web_page` 来源，状态从 `pending` 轮询到 `ready`。
4. 空间内建会话，按严格边界提问，助手消息带 Citation。

## 6. 常见问题

**端口被占用（`8000` / `5173`）**

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 8000,5173 } | Select-Object LocalPort,OwningProcess
Stop-Process -Id <OwningProcess> -Force
```

也可换端口启动：后端 `--port 8001`，前端 `npm.cmd run dev -- --port 5174`；换后端端口时要同步改 `front/.env.development` 的 `VITE_PROXY_TARGET`。

**表结构报错 / 迁移不兼容**

Phase 2 相对 MVP 有破坏性变更（新增 User、`owner_id`、Chunk 等）。本地直接清空重建：

```powershell
cd backend
Remove-Item -Force .\data\knowledgescope.db -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\data\chroma -ErrorAction SilentlyContinue
```

**问答或入库返回「未配置模型」**

`backend/.env` 的 `DEFAULT_CHAT_BASE_URL` / `DEFAULT_CHAT_API_KEY` / `DEFAULT_CHAT_MODEL` 与 `DEFAULT_EMBEDDING_*` 为空。填好后重启 uvicorn；也可在「模型设置」建个人档并在提问时指定 `chatModelProfileId` / `embeddingModelProfileId`。

**问答返回 502，detail 里带 `WinError 10013` 或「连接被本机拒绝」**

这不是业务代码报错，而是本机安全软件/网络策略拒绝了这个进程向该域名的出站连接。Windows 上常见于公司装的安全客户端（如 Sangfor aTrust / EAIO）按域名放行，同一个域名换个方式解析或换台机器表现就不同，所以时好时坏。可以按顺序排查：

```powershell
# 能不能建连：看 DeepSeek 是否被拦
Test-NetConnection api.deepseek.com -Port 443

# 换一个域名试试，确认是单域名被拦还是整体断网
Test-NetConnection ark.cn-beijing.volces.com -Port 443
```

确认是单域名被拦时，不要改代码绕过：在「模型设置」新建一个 `base_url` 指向放行名单内地址的同用途配置档，提问时选中它即可。后端对这类拒绝不再重试，会直接把地址和原因回给前端。

**问答返回 502，detail 提到「输出上限已被推理内容占满」**

所选的聊天模型是推理模型（会先输出内部推理再给正文）。`CHAT_MAX_OUTPUT_TOKENS` 太小时，`max_tokens` 可能全被推理内容吃掉，正文为空、`finish_reason=length`。把 `CHAT_MAX_OUTPUT_TOKENS` 调大（例如 `4096`），或换成非推理模型。

**来源一直 `pending` 不变**

后台入库 worker 随应用启动。检查后端日志是否随 `uvicorn` 正常启动；worker 只会继续处理仍为 `pending` 的来源，进程重启后会接着跑。

**前端 404 / 跨域 / SSE 连不上**

确认 `front/.env.development` 中 `VITE_API_BASE_URL` 留空（走 Vite 代理）、`VITE_PROXY_TARGET` 与后端实际端口一致。JWT 密钥与模型配置只放 `backend`，不要写进 `front`、`shared`。

**PowerShell 拒绝执行 `Activate.ps1`**

改用 `.\.venv\Scripts\python.exe -m uvicorn ...`（见第 3 节），或仅对当前会话放开策略：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
